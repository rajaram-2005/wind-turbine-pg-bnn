# Safety, Scope, and Non-Goals

This document defines what this repository is, and — critically — what it is
**not**.

## This system IS:

- An **advisory** Remaining Useful Life (RUL) predictor for wind-turbine
  drivetrains (gearbox, generator, main bearing).
- A research-grade Physics-Guided Bayesian Neural Network (PG-BNN) that
  quantifies **epistemic** (model / data-coverage) and **aleatoric**
  (sensor / process) uncertainty.
- A telemetry-compression utility (AeroZip-style) useful for archival of
  high-frequency SCADA channels.
- A calibration and evaluation harness to measure predictive quality.

## This system IS NOT, and will NOT be built to:

1. **Directly actuate turbine hardware.** No torque setpoints, pitch
   commands, speed limits, breaker trips, or yaw commands are emitted from
   this code. Such commands require certified SIL-rated controllers, OEM
   integration, and site-specific safety cases.
2. **Generate Lockout/Tagout (LOTO) procedures.** Compliant LOTO is
   equipment-specific, written by a qualified person, and controlled under
   OSHA 29 CFR 1910.147 / ISO 14118. Generic LOTO text generated by a model
   can be lethal if followed.
3. **Issue part numbers, torque values, or maintenance "recipes"** as
   authoritative work instructions. Any maintenance action requires the
   OEM's service manual and a qualified technician.
4. **Self-modify in production.** "Recursively self-improving" control code
   is incompatible with IEC 61508 / ISO 13849 functional-safety practice
   (no version control, no audit trail, no deterministic review). This repo
   does not, and will not, implement autonomous self-deployment loops.

## Safety gate

`src/utils/safety.py` exposes `AdvisoryRecommendation` and a runtime check
that blocks any output field that looks like a direct actuation command
(throttle percentages, RPM setpoints, LOTO steps, part SKUs). If such a
field is requested, the code raises `SafetyBoundaryError`.

The intent is defensive: even if a future contributor accidentally (or
intentionally) wires the predictor into a control path, the safety gate
will refuse to emit actuating payloads.

## Correct usage pattern

1. Run `predict_rul()` against offline or streaming telemetry.
2. Receive an `AdvisoryRecommendation` containing:
   - predicted RUL (days), with uncertainty bands,
   - physics-violation flags (vibration / temperature / RPM / viscosity),
   - *suggested* next-inspection window,
   - free-text engineering rationale.
3. A reliability engineer reviews the recommendation, cross-checks against
   SCADA trends, CMS (vibration) trends, oil-analysis history, and the
   turbine's maintenance manual.
4. Any control action (curtailment, derate, stop) is issued through the
   site's existing certified SCADA / WEMS by an authorized operator.
